Mission & Problem

Mission: make it easy for graduating students in Turkey to discover, compare, and apply to master's programs across Europe — without paying agency commissions and without trusting opaque rankings.

The problem

  • Information is scattered. Tuition, deadlines, language requirements, and curricula live in 200+ separate university sites, often outdated or in the local language.
  • Agencies are biased. The dominant pre-application channel in Turkey is a study-abroad agency that earns commissions from a subset of universities — neutrality is structurally impossible.
  • Rankings don't capture fit. A QS-top-50 school can still be wrong for a student's field, budget, or career goal.
  • Language asymmetry. Students whose English is a working second language must parse dense academic prose to compare options.

Who it's for

  • 3rd / 4th-year undergraduates & recent graduates in Turkey.
  • Looking at a master's in Europe (Italy, Netherlands, Germany, UK, France, Spain, Nordics, etc.).
  • English-taught programs preferred but not exclusive.
  • Budget-sensitive — a free tier matters; a €20 unlock should feel obviously worth it.

Solution & Product

EdFind aggregates verified master's-program data into one searchable database and uses an AI matcher to rank programs against a student's structured profile. The product has five user-facing surfaces:

1 · Profile Quiz

9 structured questions covering destinations, field, budget, duration, English level, scholarships, career goal, academic focus (research/applied/balanced), and work experience.

/quiz · client-side state with localStorage draft · answers_version: 2

2 · AI Matching

DeepSeek V4 Flash receives the profile + compressed catalog, returns a ranked top-3 with score (0-100) and one-sentence rationale. ~$0.003 per match, ~16k input tokens at current catalog size.

/results/[matchId] · server-only · no fallback (errors surface to the user instead)

3 · Free-text Search

"I want a 1-year MSc in data science under €15k in the Netherlands or Germany" → DeepSeek parses to ValidatedAnswers, then the same matcher path runs.

/search · shared backend in lib/server/persist-and-match.ts

4 · Shortlist & Compare

Save programs across results / search / detail pages. Side-by-side comparison at /compare?ids=….

/shortlist · backed by a per-user table

5 · Application Tracker

Kanban view with status, notes, and deadline per program. Feature-flagged for clean rollback via NEXT_PUBLIC_ENABLE_APPLICATIONS.

/applications · forward + rollback migrations both kept

6 · University & Program Pages

SEO-targeted detail pages at /universities/[slug] and /programs/[uni]/[prog] — Server Components, render at request time, public (no auth required).

Score-bar visualisations + Framer Motion entrance animations.

Data Sources & Verification

The catalog is built by parallel research agents that scrape official university postgraduate pages, then verified by a second pass of agents that cross-check each program against its source page.

Sourcing pipeline

  1. Discovery. Parallel research agents (Claude / subagents) read each university's English-language postgraduate index and extract candidate programs.
  2. Normalisation. Each candidate becomes an idempotent SQL INSERT … ON CONFLICT DO UPDATE block in supabase/seed.sql, keyed on (university_id, slug).
  3. Verification. A second wave of agents independently re-reads the source pages and reports discrepancies. The most recent pass touched all 197 programs across 5 regional batches (UK+IE, DACH, Nordics+Baltics+CEE, BNL+FR, Southern).
  4. Patching. Verifier output is fed into scripts/apply-verifier-fixes.mjs — a one-off patcher that locates each INSERT block by (uni_slug, prog_slug) and replaces specific fields in place.
  5. Re-seed. scripts/db-migrate.mjs pushes the patched seed to Supabase. The seed is idempotent, so re-running converges the DB to the file.

Categories of errors caught

  • Language mistagging (3) — ETH Architecture, LMU Eastern European Studies, Bologna MSc CS all flagged as English but actually local-language.
  • Tuition figures (12) — NTNU's post-2023 fees most affected; one total-vs-annual mixup at a French business school; Charles EU/non-EU mixup.
  • Duration errors (4) — ETH Architecture, RWTH Automotive, Lund Finance, Nova BA.
  • Wrong dates (7) — LBS intakes, WU Vienna start, ETH + Geneva deadlines.
  • Nonexistent program (1) — UiO MA European and International Relations doesn't exist in UiO's catalog.

Known open issues

  • Portuguese programs publish program TOTALS not annual fees (Nova SBE) — needs a per-currency / per-mode column or a free-text field.
  • A handful of grey-zone tuition figures (~20-30% off, e.g. HEC Master in Strategic Management) flagged but not yet patched.
  • All tuition + deadline data is point-in-time and should be refreshed annually.

Key Decisions

Architectural rationale lives under docs/decisions/. Three ADRs accepted to date.

ADR 0001 — Tech stack: Next.js 16 + TS + Tailwind + shadcn + Supabase + Vercel

Context: Content-heavy public surface (SEO-sensitive), AI-driven matching, tiered paywall, application tracker. Solo / small team, EU audience, no secrets to browser.

Decision: Next.js App Router for SSR + RSC + Server Actions, Tailwind + shadcn for owned UI components, Supabase for DB+Auth+Storage+RLS, Vercel for hosting. Stripe deferred.

Rejected: Plain React + Express (doubles deploy surface, gives up SSR for SEO). Firebase (document model fights relational data). MUI/Chakra (harder to bend toward bespoke illustrated design).

ADR 0002 — Database: Supabase Postgres with RLS as hard backstop

Context: Heavily relational data (unis → programs → matches → reviews). Need tier-gated reads enforced beyond app code. Want fast time-to-first-feature.

Decision: Supabase. RLS lets tier gating live in the DB; app bugs can't bypass it.

Rejected: Firebase (relational fit), PlanetScale + Auth.js + S3 (three integrations to glue), self-hosted (ops burden user wants to avoid), Convex (provider-specific patterns).

ADR 0003 — AI provider abstraction at lib/ai/index.ts

Context: Provider pricing/latency/quality shifts fast. Today's choice probably isn't 12-month-from-now's choice. Leaking AI keys is the biggest single risk.

Decision: Thin provider-agnostic wrapper. Feature code imports from lib/ai/index.ts with a stable chat({ messages, schema?, model? }) interface. DeepSeek is default, OpenAI is configured backup. All AI calls server-only.

Rejected: Use OpenAI SDK directly (global refactor to swap), use Vercel AI SDK as the abstraction (may adopt later behind same facade), LangChain (too heavy).

Product-level non-negotiables

  • Tier checks must live in DB RLS — not just in JS.
  • Never silently boost partner universities in Full Access matching. Partner content is content-tagged and surfaced as a separate tier.
  • i18n-ready strings — v1 is English, audience is Turkish; write for swap, not rewrite.
  • Docs are load-bearing. Behavior/schema/architecture changes update the relevant .md in the same session.

Future / Phase 10+

The MVP roadmap is complete; what's next is feature breadth and business plumbing.

Phase 10 — Tier billing

Stripe wiring: checkout for Partner (€1.99/mo) + Full Access (€20 one-time). The profiles.tier column already exists; this is mostly Stripe webhooks → tier update + RLS policy hook-up.

Planned

Turkish localisation

v1 is English-only but audience is Turkish. Strings are written for swap-not-rewrite. Likely next-intl + a parallel tr namespace, plus a translation pass on all user-visible copy.

Planned

Catalog expansion

Current: 196 programs across 18 countries. Notable thin spots: France (1 partner), Scandinavia (single programs at some Nordics), CEE coverage. Target a verified ~300 programs / ~80 universities before public launch.

Backlog

Scholarships

A scholarships table cross-referenced by country/program/student-citizenship. Surfaced on detail pages and as a filter in the matcher.

Backlog

Reviews

Verified student reviews tied to program_id + user_id. Requires anti-fake review logic and probably moderation.

Backlog

Real signal data

Once accounts are common, swap the prompt-only matcher heuristics for actual conversion/acceptance signal. Today's matcher is intentionally not gold-plated.

Backlog

Marketing surface

A landing-page funnel aimed at Turkish-speaking students. Likely Instagram + university-society outreach. Not yet started.

Backlog

Observability

Structured server logs + a single error tracker (Sentry / similar). Not in MVP. Likely Phase 10 alongside billing — once money is on the line, paging matters.
