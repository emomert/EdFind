# Turkish language support (i18n)

**Status:** live (2026-07-20) · **ADR:** [0007](../decisions/0007-i18n-next-intl.md)

EdFind ships in **English (default) and Turkish**. The locale is a cookie
(`edfind_locale`), not a URL segment — URLs are identical in both languages.
A `LanguageSwitcher` (EN | TR pill) in the site header sets the cookie via a
Server Action. Next.js returns the translated React tree in the same
roundtrip after the cookie changes; the switcher does not issue a second
`router.refresh()`. The selected pill updates optimistically while that
response is in flight.

## Architecture

| Piece | Where |
| ----- | ----- |
| Locale config (locales, default, cookie name) | `lib/i18n/config.ts` |
| Per-request locale + message loading | `i18n/request.ts` (wired by `createNextIntlPlugin()` in `next.config.ts`) |
| Cookie-setting Server Action | `lib/i18n/actions.ts` |
| Switcher UI | `components/i18n/language-switcher.tsx` (optimistic selection; rendered in `site-header.tsx`) |
| Messages | `messages/{en,tr}/<namespace>.json`, aggregated by `messages/{en,tr}/index.ts` |
| DB-value display names (countries, cities, languages, fields) | `lib/i18n/data-labels.ts` |
| Provider + `<html lang>` | `app/layout.tsx` (`NextIntlClientProvider`) |

### Namespaces and ownership

One JSON file per feature area, same key tree in `en` and `tr`:

`common` (header/footer/nav/meta, shared UI) · `auth` (login) · `home`
(homepage, /start, welcome tour, quiz preview) · `quiz` · `search` · `results`
(results, compare, shortlist) · `catalog` · `university` (detail pages,
housing) · `community` · `applications` (tracker + document studio) ·
`premium` · `legal` (terms, privacy, technical report) · `demo` · `server`
(user-facing error strings returned by shared server code, e.g.
`lib/server/persist-and-match.ts`).

Adding a namespace = new JSON in both locale folders + an import in **both**
`messages/{en,tr}/index.ts`.

## Usage patterns

```tsx
// Client component or non-async Server Component
import { useTranslations } from "next-intl";
const t = useTranslations("quiz");
<p>{t("intro.title")}</p>

// Async Server Component / Server Action / metadata
import { getTranslations } from "next-intl/server";
const t = await getTranslations("catalog");
export async function generateMetadata() {
  const t = await getTranslations("catalog");
  return { title: t("meta.title") };
}

// Interpolation (ICU)
t("programCount", { count: 3 })        // "3 programs" / "3 program"

// Rich text with an embedded link/tag
t.rich("agreement", { link: (chunks) => <Link href="/terms">{chunks}</Link> })

// Current locale (e.g. for data-label helpers)
import { useLocale } from "next-intl";            // client / non-async RSC
import { getLocale } from "next-intl/server";     // async RSC
import { localizeCountry } from "@/lib/i18n/data-labels";
localizeCountry(university.country, locale as Locale)
```

DB values (country, city, teaching language, field of study) are stored in
English. When displaying them, run them through the `localize*` helpers from
`lib/i18n/data-labels.ts` — they fall back to the English value when unmapped.

Quiz question/option labels stay in `lib/quiz/schema.ts` as the English
source of truth (the AI prompt builder may read them); the quiz UI overlays
translations from the `quiz` namespace with `t.has(key) ? t(key) : label`
fallback keyed by question id + option value.

## Product rules

1. **"EdFind" is never translated or transliterated** — it's the brand.
2. **University and program names stay English** everywhere (proper nouns,
   and they must match the official names students will apply under). City
   names may use Turkish exonyms (Münih, Viyana) via `localizeCity`.
3. **Stored values never change.** Quiz option `value`s, application status
   ids (`interested`, …), kanban column ids, DB fields, query params — only
   *labels* are translated. `ANSWERS_VERSION` does not bump for translations.
4. **What deliberately stays English:**
   - Mock community content that simulates user-generated posts (reviews,
     chat messages, questions) — real UGC will arrive in whatever language
     users write.
   - AI document studio output (CVs, cover letters) — these are submitted to
     European universities in English. The studio *UI* is translated.
   - The live system prompts shown on `/technical-report` — the page renders
     the real English prompts; its surrounding copy is translated.
   - `app/global-error.tsx` — renders outside the provider (root layout
     crashed), so it keeps hardcoded English strings.
5. **AI output follows the locale**: the matcher writes its rationale in the
   active locale, and the free-text parser accepts Turkish input (see
   `lib/ai/`).

## Turkish style guide

- **Tone:** informal, warm "sen" — consistent with the brand voice
  (`docs/design/brand.md`). Never "siz" mid-sentence after a "sen" elsewhere.
- **Sentence case** for headings and buttons ("Programları keşfet", not
  "Programları Keşfet"), matching the English design.
- Respect Turkish casing (İ/ı): "İngilizce", "İşletme". Avoid relying on CSS
  `uppercase` for Turkish strings containing i/İ.
- Loanwords the audience uses freely stay: **Premium, CV, kampüs, katalog**.
- ICU placeholders are named (`{count}`, `{university}`) — reorder freely for
  natural Turkish word order; never concatenate string fragments.

## Testing / gotchas

- A missing key renders the key path in the UI and logs a console error —
  keep `en` and `tr` trees identical.
- `getRequestConfig` reads `cookies()`, so every page is dynamically rendered
  (they already were — the header reads the auth cookie).
- Setting the locale cookie in the Server Action already invalidates the
  client router cache and re-renders the current page/layout. Do not add
  `router.refresh()` after `setLocale`; that creates a redundant second
  request and makes language switching noticeably slower.
- The demo route (`/demo`) and its recording script run under the default
  `en` locale unless the cookie says otherwise, so recorded videos are
  unchanged.
